## 직원별 실제 AI API 연결 — 개발 브랜치

대표님이 화면에서 직원 1~10번과 AI를 선택하고 직접 `API 실행 · 사용료 발생`을 누르면, Cloudflare Worker가 **등록된 해당 서비스의 공식 API**로 텍스트 업무를 보냅니다. 역할별 지시문은 직원마다 다르고, 결과는 기존 보고함으로 반환됩니다.

| 웹 서비스 | 서버에서 필요한 Secret | API 모델 | 범위 |
|---|---|---|---|
| ChatGPT | `OPENAI_API_KEY` | `gpt-4.1-mini` | 기획·글쓰기·검수 텍스트 |
| Gemini | `GEMINI_API_KEY` | `gemini-3.8-flash` | 조사·기획 텍스트 |
| Claude | `ANTHROPIC_API_KEY` | `claude-sonnet-5-5` | 블로그·SNS·검수 텍스트 |
| NVIDIA Nemotron | `NVIDIA_API_KEY` | `nvidia/nemotron-3-ultra-550b-a55b` | 조사·검수 텍스트 |

API 모델 ID·호출 방식은 각 제공자의 공식 API 문서를 기준으로 작성했습니다. **아직 외부 서비스의 실제 API 키 설정과 유료 실행 성공은 확인되지 않았습니다.** `/api/status`에 표시하는 `providers[...].configured`는 서버 키 유무 확인이며, `verified:false`는 실제 API 응답 미검증을 뜻합니다. 선택한 API의 키가 없으면 503을 반환하고 **다른 서비스로 자동 대체하지 않습니다.**

기존 하루 20회·전체 200회 제한, 동일 요청 중복 차단, 한 번에 한 유료 요청, 통신 실패 후 결과 조회 원칙을 모든 텍스트 공급자에게 공통 적용합니다. **외부 공급자의 별도 요금·충전 설정과 다른 사용처의 API 비용은 이 한도로 통제되지 않습니다.** 자동 호출은 없으며 버튼을 직접 누를 때만 전송됩니다.

직원 3·6·7번의 Runway/Higgsfield/CapCut 업무는 **AI가 제작 계획과 지시문을 텍스트로 작성할 수 있을 뿐**, 해당 도구의 실제 영상 생성·파일 편집 API 연동은 별도입니다. Microsoft·Canva·Metricool 사이트 열기 링크 역시 API 실행 연결이 아닙니다. 홈페이지 로그인이나 ChatGPT 커넥터 연결이 Cloudflare 서버에 자동 전달되지는 않습니다.

현재 PR은 **미배포** 상태입니다. 클라우드 서버의 실제 Secret 추가·서비스 배포·유료 테스트 실행은 대표님 승인 후 진행합니다. 설정한 API 키를 GitHub 소스, 채팅, 브라우저 또는 Telegram에 넣지 마세요.

# v6.3 · GPT 시험 연결 준비

총괄 직원의 지시를 Cloudflare Worker를 통해 GPT에 전달하는 선택 기능을 추가했습니다. 기본 상태는 미연결입니다. API 키는 서버 Secret에만 저장하고, 별도 사무실 접속 암호로 인증합니다. 일 20회·전체 200회 제한을 D1에서 적용합니다. 실제 서버 설정과 유료 GPT 호출은 별도 확인이 필요합니다.

설치와 보관·비용 범위: [server/README.md](server/README.md). 기존 8개 도구의 수동 전달, 업무 기록, 캐릭터와 설치 기능은 유지합니다.

## 1호 휴대폰에서 내려온 사무실 업무 지시함 (개발용)

- `1호 동백대리 → 사무실 업무 지시함`을 노트북 작업 화면에 추가했습니다. 인증 후 `1호 업무 확인`을 누르면 서버에 등록된 최근 업무를 조회합니다.
- 확인 후에는 30초마다 새 업무를 조회하지만 AI 실행/결제/게시를 시작하지 않습니다. 브라우저가 숨겨졌거나 사용자가 답변을 작성 중이면 해당 자동 조회를 건너뛰어 입력 내용을 보존합니다.
- 10명 현황판의 담당 직원에게 `1호 업무 지시 접수 · 실행 전`을 표시하고, 사람이 확인한 초안을 회신하면 `1호에 초안 회신 · 검수 필요`로 전환합니다. 초안을 보냈다는 사실은 대표 검수 승인이나 게시 완료가 아닙니다.
- 신규 업무 접수 자체는 **1호 Hermes가 실제 인증된 서버 지시 API를 호출해야** 가능합니다. 현재 Termux Hermes와 이 업무 API의 실기기 연동은 아직 미검증입니다. 정식 서버 배포도 보류 중입니다.
- [1호 연결 상태 계약](server/PHONE1_STATUS_CONTRACT.md)과 별개로, 서버의 `/api/phone1/agent/dispatch` → `/api/phone1/inbox` → `/api/phone1/inbox/result` → `/api/phone1/agent/status` 경로로 시험합니다.

## 1호 휴대폰 Hermes 실시간 상태 수신 (검토용)

- **1호 휴대폰이 실제로 보낸 상태 신호**를 노트북 동백사무실의 `1호 휴대폰 · Hermes 실제 상태`에 표시합니다. 사무실은 30초 간격으로 서버를 조회합니다.
- 상태: `idle`(대기), `working`(실제 작업), `paused`(일시정지), `error`(오류). 서버는 마지막 신호로부터 120초가 지나면 `stale`로 표시하고, `working` 상태를 무효화합니다.
- 서버 인증은 기존 사무실 접속 암호와 별도의 Hermes 장치 토큰을 사용합니다. 장치 비밀키는 노트북 UI에 전달되지 않습니다.
- `server/phone1_presence_sender.py`는 Termux에서 관측한 상태를 **1회 전송**하는 참고용 어댑터입니다. 이 파일만 실행한다고 Hermes의 실제 이벤트를 자동으로 수집하거나 반복 전송하지 않습니다. 자동 수집은 1호 휴대폰에서 검증된 Hermes 실행 이벤트와 연결할 때만 가능합니다.
- Cloudflare 배포·실제 휴대폰 설치·모델 실행은 아직 수행하지 않았습니다. 정식 배포 전까지 온라인 여부를 추측해서 표시하지 않습니다.

## Hermes 업무 대기함 연결 (검토용·미배포)

현재 코드는 사무실에서 **직원 10명에게 초안 작성 업무를 접수**하는 별도 Hermes 대기함을 지원합니다. 이 기능은 기존 GPT 유료 실행과 분리되며, 서버 D1에 업무만 기록합니다. 휴대폰 Hermes가 자동으로 작업을 시작했다고 표시하지 않습니다.

- 사무실에 `Hermes 업무 연결 · 시험판` 입력 화면이 추가됩니다. 접수 기록은 같은 브라우저에 저장되지만 접속 암호는 저장하지 않습니다.
- 별도 인증 토큰을 사용하는 수신용 API와 Termux Python 클라이언트가 있습니다. 이 클라이언트는 업무를 수신하고 수동으로 작성한 텍스트를 전달하며, Hermes CLI나 Telegram을 자동 실행하지 않습니다.
- 중복 수신 및 중복 결과 반영을 차단합니다. 수신 후 통신이 끊기면 자동 재실행하지 않고 서버에서 수신 여부를 확인할 수 있습니다.
- Hermes 결과가 도착해도 상태는 '초안 도착 · 검수 필요'이며, 자동 게시/발송/결제되지 않습니다.
- **배포·실행 전 조건:** Cloudflare 서버에 별도 `HERMES_AGENT_TOKEN` 시크릿을 등록하고, Hermes 1호 휴대폰과의 호환성 및 비용·도구 권한을 확인해야 합니다. 현재 해당 설정을 변경하지 않았습니다.

정확한 절차와 한계는 [Hermes 업무 연결 안내](server/HERMES_BRIDGE.md)를 참고하세요.

## 검토용 10명 업무 현황판 (개발 브랜치)
 
- 총괄 1명, 조사·기획 2명, 영상·디자인 3명, SNS 운영 2명, 검수·성과 2명을 업무 배정 목록에 표시합니다. 기존 4인 시뮬레이션 화면 자체는 아직 변경하지 않았습니다.
- 업무 현황판은 실제 브라우저 업무 기록에 저장된 상태를 읽어 표시합니다. GPT 요청/결과, 수동 지시문 복사/결과 입력, 대표 보고 접수를 구별합니다. 생성 사실이 확인되지 않은 결과는 자동 성공으로 표시하지 않습니다.
- GPT 총괄 분장 단계는 연결 서버에 요청을 시작할 때 해당 담당자의 진행 상태가 표시됩니다. 단계가 끝났다는 표시는 서버 응답이 저장된 경우에만 사용합니다.
- 5~10번 직원에게도 수동 업무 지시와 결과 기록을 할 수 있습니다. 결과가 기록된 업무는 보고함에 바로 접수되지만 직원이 대표실까지 걸어가는 시각 연출은 아직 연결되지 않았습니다.
- 실제 GPT 요청은 기존 Cloudflare Worker 설정과 대표의 유료 API 실행 승인이 있어야 가능합니다. Hermes·Telegram 자동 처리, 외부 서비스 로그인, SNS 자동 업로드, 실시간 웹 검색 기능은 이 개발 변경에 포함되지 않습니다.
- 결과는 기존 브라우저 로컬 저장소에 남습니다. 기기 간 동기화는 없으며 업로드·게시 기능은 실행하지 않습니다. `node tests/team10-state.cjs`와 `node tests/team10-live-board.cjs`로 상태·브라우저를 검수합니다.

## 사용 중인 AI에 업무 전달하기 (v6.2)

사무실의 **AI 업무 도구**에서 ChatGPT, Runway, Microsoft 365, Higgsfield AI, Metricool, Canva, CapCut, Claude를 새 창으로 엽니다. 서비스의 기존 계정으로 로그인해 이용하며, 웹 구독이나 이 대화의 도구 인증을 사이트로 이전하지 않습니다. API 호출이나 자동 제출은 수행하지 않습니다.

1. 담당 직원과 서비스를 선택하고 업무 지시를 작성합니다. 직원 상세의 **이 직원에게 AI 업무 맡기기**로도 시작할 수 있습니다.
2. **지시문 복사**를 누른 뒤 **AI 열기**로 이동해 입력창에 붙여넣고 직접 실행합니다. 자동 복사가 제한되면 표시된 지시문을 직접 복사합니다.
3. 서비스에서 받은 결과나 결과 링크를 **결과 기록**에 저장합니다.
4. **대표에게 보고**를 누르면 담당 직원이 대표실로 이동하고, 보고가 접수된 뒤에만 완료로 표시됩니다. 시뮬레이션을 초기화해도 결과는 보관하며 다시 보고할 수 있습니다.

업무 지시와 결과, 직원별 도구 선택은 같은 브라우저의 저장소에 유지됩니다. 기기 간 자동 동기화는 하지 않습니다. **업무 기록 백업**으로 JSON을, 개별 업무에서는 Markdown 보고서를 내려받을 수 있습니다. 비밀번호나 API 키 입력은 받지 않습니다. 초기 목록의 요금제나 로그인 상태는 사이트에서 확인·표시하지 않습니다.

자동 검사 `npm run test:ai-desk`는 실제 복사, 새 창 열기, 결과의 안전한 표시, 저장과 백업, 직원의 보고 완료 시점, 초기화 시 결과 보존, 복사·저장 제한과 모바일 표시를 검사합니다. 새 창 목적지는 검사 중 가로채므로 실제 서비스에서 작업하거나 크레딧을 사용하지 않습니다.

## 대표·탕비실 좌석·작업실 정원 (v6.1)

대표의 몸통을 가리던 수평 영역을 책상 뒤쪽의 기울기에 맞췄습니다. 탕비실에서는 배경에 그려진 두 의자의 좌판에 직원의 앉은 위치를 맞추고, 추가 직원에게는 별도 의자를 표시합니다. 작업실 왼쪽 정원에는 앉아서 쉬는 동백이를 표시합니다. 정원 확대 화면의 기존 동백이 애니메이션은 유지합니다.

이전 화면이 보이면 공개 주소의 `latest.html`을 여세요. 새 빌드마다 별도 릴리스 경로로 이동하므로 이전 서비스 워커 캐시와 구분됩니다. 이전 릴리스 파일과 그림은 보존합니다.

`Review office layout` GitHub Actions는 검토 브랜치에서 실제 Chromium으로 수정 전후·모바일 화면, 최대 6명의 탕비실 좌석, 직원 이동·라디오·캐시 복구를 검사하고 화면을 저장합니다. 배포 후에는 공개 HTTPS 주소의 코드가 빌드와 일치하는지, 장면과 모바일 화면이 열리는지도 확인합니다. 워크플로에는 배포 권한이 없습니다.

기존 `test:pwa`의 업데이트 버튼을 통한 새로고침 검사에서는 시간 초과가 관찰됐습니다. 이 버전은 기존 설치 업데이트 코드를 변경하지 않으며, 최신 화면 확인에는 위 `latest.html` 경로를 사용합니다.

단일 HTML을 직접 확인하려면 `dist/주식회사동백-v3.html`을 Chrome 또는 Edge로 여세요. 파일 이름의 v3는 기존 내보내기 이름이며, 화면 제목은 v6.1입니다.

## 자세·청소·정원·운동 음악 (v6)

실내 꽃과 식물은 이전 그림의 약 10%만 남기고, 체력단련실 내부는 모두 없앴습니다. 바깥 정원은 유지합니다. 기존 `roof` 내부 키는 호환을 위해 남겼지만 화면에는 G 정원으로 표시하고 이동 층수는 1층으로 처리합니다.

직원은 체력단련실에서 운동복과 손으로 아령을 잡은 두 자세로 바뀝니다. 음악은 오리지널 신시사이저 루프(116 BPM)이며 입장 동작으로 재생을 시도합니다. 브라우저가 소리를 막으면 음악 버튼으로 켤 수 있습니다. 음소거 선택은 기기에 저장되고, 공간을 나가거나 탭이 숨겨지거나 신청곡이 재생되면 멈춥니다.

청소 담당자는 40대 후반 여성의 근무복·물걸레 자세 두 장면으로 표시합니다. 탕비실에서는 손과 컵을 함께 그린 앉은 자세를 사용합니다. 대표는 책상 뒤 의자에 맞춰 크기와 가림을 조정했습니다.

## 이전 화면이 계속 보일 때

공개 주소 뒤에 `latest.html`을 붙이면 빌드 해시로 나뉜 새 경로로 이동합니다. 예전 서비스 워커와 HTTP 캐시가 저장한 동일 이름의 스크립트를 다시 쓰지 않도록 하는 복구 경로입니다. 기존 이름 설정은 같은 출처의 저장소에서 유지됩니다. 서비스 워커는 설치할 때 HTTP 캐시를 재검증해서 앱 파일을 저장합니다.

## 시안 캐릭터와 로비·체력단련실 (v5)

직원과 동백이는 투명 배경의 회화풍 이미지로 표시합니다. 서 있는 자세와 앉아 일하는 자세를 나눠 실제 시뮬레이션 위치에 겹칩니다. 동백이는 두 자세를 번갈아 표시하며 정원을 이동합니다. 얼굴을 매 프레임 새로 생성하는 방식은 아니며, 이동·타이핑·운동 애니메이션은 이 그림을 움직여 표현합니다.

로비와 체력단련실은 작업실과 같은 원목, 크림색 벽, 동백꽃과 조명으로 새로 제작한 빈 배경을 사용합니다. 안내 직원과 청소 담당자, 운동 중인 직원은 배경과 별개입니다. 배경·캐릭터 파일은 오프라인 캐시에 포함되며, 설치된 앱에서 업데이트가 준비되면 화면 위 버튼으로 적용합니다.

## 퇴근길 라디오

‘퇴근길 라디오’에서 직원별 곡명·가수·사연을 신청하고 대표가 선곡합니다. ‘직원 신청곡 받기’는 가상의 신청과 오리지널 데모 음악을 만듭니다. 실제 곡명만 입력해서 스트리밍 서비스를 재생하지는 않습니다. 음악 파일을 선택하면 기기 안에서 재생하며 서버에 업로드하지 않습니다. 파일과 신청 목록은 새로고침·초기화 시 사라집니다.

곡이 끝나면 신청 직원이 퇴근하는 옵션이 기본으로 켜져 있습니다. 중지·재생 실패 시 퇴근하지 않습니다. 승강기가 사용 중이면 기다립니다. ‘퇴근 시뮬레이션’은 신청곡 입력으로 안내하고, ‘음악 없이 퇴근하기’로 기존 퇴근 동작을 바로 실행할 수도 있습니다.

## 움직이는 사무실 v4

첫 화면은 Camellia Atrium 사무실입니다. 생성한 배경에서 사람과 강아지를 제거하고, 업무 상태에 따른 별도 SVG 캐릭터를 겹쳐 표시합니다. 그림 속에 고정된 직원은 없습니다. 대표실·탕비실·옥상은 같은 인테리어의 해당 부분을 확대하며, 로비·체력단련실·엘리베이터는 전용 공간입니다. 직원은 현재 위치에 한 번만 나타납니다.

휴대폰에서는 전체 사무실을 먼저 표시합니다. ‘확대 보기’로 캐릭터를 크게 보고 좌우로 이동하고, ‘전체 보기’로 돌아갑니다. 기존 앱에서는 설치 정보에서 ‘새 버전 적용’을 눌러 업데이트합니다. 업무는 실제 AI 호출 없는 시뮬레이션입니다.

# 주식회사 동백 · AI 사무실 v3

실제 AI 호출이나 외부 배포 없이 실행되는 한국어 사무실 시뮬레이션입니다. 참고 이미지의 밝은 미니어처 분위기와 구획된 사무실 배치를 SVG로 구현했습니다. 외부 이미지·폰트·CDN을 사용하지 않습니다.

## 실행

Python 3가 있는 환경에서 저장소 폴더로 이동하여 실행합니다.

```bash
npm start
```

또는:

```bash
python3 -m http.server 3000 --bind 0.0.0.0
```

로컬 PC에서는 브라우저에서 `http://localhost:3000`을 엽니다. 서버 종료는 `Ctrl+C`입니다. 현재 클라우드 온보딩 화면은 localhost 웹 미리보기를 지원하지 않습니다.

## 설치 없이 여는 단일 HTML

```bash
npm run export
```

기본 출력은 `dist/주식회사동백-v3.html`입니다. 저장된 HTML을 Chrome이나 Edge로 열면 됩니다. 외부 스크립트나 서버가 필요하지 않습니다. 파일 경로는 작업 공간 내부 경로이며 채팅 다운로드 링크가 아닙니다.

## 공간과 직원

- **3F 작업실**: 6개의 지정 좌석, 개인 컴퓨터, 의자, 파티션, 수납장과 통로. 작업자는 앉아서 모니터를 봅니다.
- **4F 대표실**: 대표가 상주하며 엘리베이터에서 내린 직원의 결과 보고와 질문을 받습니다.
- **3F 탕비실**: 승강기 왼쪽 뒤편의 커피 바·커피 머신·냉장고, 테이블·의자·휴식 소파.
- **2F 체력단련실**: 러닝머신·운동 벤치·덤벨·매트. 휴식 중인 직원만 표시됩니다.
- **RF 옥상정원**: 검정 프렌치불독 동백이, 전용 집, 사료가 담긴 밥그릇과 물그릇, 꽃 화단, 장난감 공.
- **1F 로비**: 업무 책상 없는 안내 데스크와 대기 소파. 여성 안내 직원과 물걸레 청소 담당자가 상주합니다.

업무와 이름을 `총괄 · 동백총괄매니져`, `자료조사 · 임채리대리`, `디자인 · 임민채공주`, `검수 · 김검수사원`으로 표시합니다. 임채리대리는 단발 여성 캐릭터, 임민채공주는 긴 머리와 리본의 여성 캐릭터입니다. 초기에는 총괄·자료조사가 작업실, 디자인이 체력단련실, 검수가 탕비실에 있습니다. 대표는 대표실, 동백이는 옥상정원에만 표시됩니다. 직원별 현재 위치는 한 곳만 유지합니다.

장면 좌표는 이전 900×650에서 **1350×975**로 확대했습니다. 작은 화면에서는 장면만 좌우로 탐색하며 페이지 전체가 가로로 넘치지 않습니다.

## 체험 순서

1. **결과 보고 / 엘리베이터**: 자리에서 일어나기 → 승강기로 이동 → 탑승 → 실제로 상승하는 승강기 장면 → 4층 도착 → 대표 앞으로 이동 → 서류를 들고 결과 보고 → 보고 접수. 전체 약 19초입니다. 접수 후에만 완료 수치가 증가하며 직원은 휴식 공간으로 이동합니다.
2. **직원 이동 따라보기**: 자동으로 장면이 바뀝니다. 수동 공간 선택 시 따라보기를 해제합니다. 다시 체크하면 이동 중인 직원을 따라갑니다.
3. **출근 시뮬레이션**: 로비 출근 인사 → 안내 직원의 환영 → 승강기 → 3층 개인 좌석. 퇴근한 직원이 있으면 먼저 다시 출근시킵니다. 최대 6명으로 좌석 중복을 방지합니다.
4. **퇴근 시뮬레이션**: 승강기 → 1층 로비 → 직원과 안내 직원의 퇴근 인사 → 퇴장.
5. **대표에게 질문**: 실제로 대표실까지 이동한 뒤 질문 대기가 됩니다. 질문 카드에서 답변하면 작업실로 돌아와 일합니다.
6. **직원 상세**: 캐릭터나 직원 목록을 클릭하여 작업 시작, 보고, 탕비실·체력단련실·옥상 휴식을 지정합니다. 키보드 Tab/Enter도 지원합니다.
7. **갱신 중단**: 5초 후 캐릭터·청소·동백이·이동 진행이 함께 멈춥니다. 재개하면 멈춘 단계부터 이어집니다.
8. **소등·이름 설정·초기화**: 이름은 브라우저 저장소에 저장하며 실제 작업 상태와 로그는 메모리에서만 유지합니다. 저장소가 제한된 브라우저에서는 이름이 현재 실행 동안만 유지될 수 있습니다. 초기화는 저장한 이름을 유지합니다.

동선은 시뮬레이션입니다. 보고·출퇴근은 단계별 이동으로 표시하며, 휴식 지정 및 질문 답변 후 작업실 복귀는 즉시 위치를 변경합니다. 동시에 한 직원만 승강기를 이용합니다. 캐릭터와 인테리어는 외부 3D 엔진 없이 SVG의 투영·음영·애니메이션으로 표현합니다.

## 검증

```bash
npm run check
```

브라우저 검증은 Playwright가 제공되는 개발 환경에서 서버를 켠 뒤 실행합니다. 앱 자체에는 설치 의존성이 없습니다.

```bash
npm run test:browser
```

다른 포트는 `APP_TEST_URL`, 시스템 Chromium은 `CHROMIUM_PATH`로 지정할 수 있습니다. Playwright 기본 브라우저 또는 `/usr/bin/chromium`을 사용합니다. 검증 대상은 공간별 인원 분리, 여성 캐릭터·앉은 자세, 전체 보고·출퇴근 동선, 승강기 상승, 질문 답변, 갱신 정지·재개, 모바일 좌우 탐색과 모션 감소 설정입니다.

## 픽셀풍 화면과 사무실 그림 (v3.1)

새 참고 이미지의 나무 바닥·벽돌 기둥·도시 창문·초록색 가구를 반영했습니다. `pixel-mode.js`는 기존 시뮬레이션의 같은 직원·위치·동선 데이터를 사용하여 픽셀 캐릭터와 공간을 그립니다. 작업자는 모니터를 향한 뒷모습이며, 여성 직원의 단발/긴 머리와 리본을 구분합니다. 기존 입체 렌더러는 대체 화면으로 코드에 남아 있습니다.

`사무실 이미지` 버튼은 생성한 별도의 콘셉트 일러스트를 보여줍니다. 일러스트 속 직원은 정적인 그림이며 실제 시뮬레이션 인원 집계에 포함되지 않습니다. 그림 원본은 `assets/office-pixel.png`, 사용자 참고 이미지는 앱에 포함하지 않습니다.

## 홈 화면 앱 설치 (PWA)

**저장한 HTML 한 파일 또는 Acode 미리보기 자체가 설치 앱은 아닙니다.** 최초 설치는 Chrome에서 **HTTPS 주소 또는 같은 휴대폰의 localhost/127.0.0.1 주소**로 설치용 폴더를 열어야 합니다. 다른 컴퓨터의 일반 HTTP 사설 IP 주소는 안전한 컨텍스트가 아니므로 사용할 수 없습니다. 휴대폰 내부 서버/Acode의 실제 실행 주소와 Chrome 설치 메뉴 제공 여부는 해당 휴대폰에서 확인해야 합니다.

```bash
npm run build:pwa
```

출력:

- `dist/dongbaek-pwa/`: 설치 가능한 정적 파일 전체
- `dist/주식회사동백-설치용.zip`: 위 폴더와 한국어 설치 안내를 포함한 ZIP. APK가 아닙니다.

로컬 개발 확인:

```bash
python3 -m http.server 3000 --directory dist/dongbaek-pwa
```

같은 기기의 Chrome에서 `http://localhost:3000`을 열어 `홈 화면에 설치`를 누릅니다. **오프라인 준비 완료** 후 앱의 설치 버튼 또는 Chrome ⋮ 메뉴의 `앱 설치 / 홈 화면에 추가`를 사용합니다. 최초 준비와 설치를 완료하면 서버가 꺼진 뒤에도 저장된 앱 화면을 열 수 있습니다. Chrome 내부 웹뷰에서는 설치 창이 나오지 않을 수 있어 `Chrome에서 열기`를 제공합니다. 설치 취소는 완료로 표시하지 않습니다.

브라우저 데이터 삭제·저장공간 정리·앱 제거 시 오프라인 파일과 저장한 이름도 지워질 수 있습니다. 다시 연결해서 준비해야 합니다. 이 작업에서는 외부 호스팅이나 공개 배포를 하지 않았으며 실제 사용자 휴대폰에 설치됐다고 보장하지 않습니다.

새 버전은 빌드를 다시 만들어 폴더 전체를 교체합니다. 빌드마다 파일 내용의 해시로 캐시 버전을 바꾸며, 준비된 업데이트는 사용자가 `새 버전 적용`을 눌러야 활성화됩니다. 이때 실행 중인 시뮬레이션은 초기화되고 저장한 이름은 유지됩니다. 다른 경로의 앱 캐시는 삭제하지 않습니다.

```bash
npm run check
npm run build:pwa
npm run export
npm run test:browser
npm run test:pwa
```

PWA 검증은 기본적으로 실행 중인 서버의 `/dist/dongbaek-pwa/`를 사용합니다. 다른 경로는 `PWA_TEST_URL`로 지정합니다. 실제 서비스워커 캐시, 오프라인 새로고침, 홈 화면 시작 URL, 이미지 오프라인 표시, 설치 취소, 명시적인 버전 업데이트와 캐시 범위를 확인합니다. 실제 Android 설치 대화상자 수락은 사용자 휴대폰에서 진행해야 합니다.

단일 HTML 내보내기에는 픽셀 렌더러와 그림을 포함하지만, `file:`에서는 설치 기능이 동작하지 않는다는 안내를 표시합니다.

### 동백꽃 아트리움 리디자인

콘셉트 일러스트를 기존의 소파 벽면·평행 책상 배치에서, 왼쪽 연결 정원과 산책길·중앙 협업 아일랜드·오른쪽 곡선형 서가와 유리 회의실로 다시 설계했습니다. 동백꽃 장식과 크림색 벽·밝은 원목·금색 조명으로 주식회사 동백의 공간을 구분합니다. 실시간 작업실도 별도의 좌측 정원 띠, 연결형 공유 책상, 창가 집중석과 단계형 서가를 갖도록 변경했습니다. 동백이는 흰 무늬 없는 검정 프렌치불독이며, 이전보다 작고 둥근 귀를 적용했습니다. 콘셉트 그림과 실제 인원·위치를 표시하는 시뮬레이션은 구분됩니다.

콘셉트 그림의 인원은 직원 4명(총괄·자료조사·디자인·검수)과 별도 대표 1명으로 맞췄습니다. 오른쪽 곡선 유리 공간은 대표 전용 집무실이며 모니터·서류·조명·전용 의자를 배치했습니다. 동백이 귀는 앞선 아트리움 그림보다 약 절반 크기의 작고 둥근 귀로 수정했으며, 실시간 캐릭터에도 반영했습니다.

## GitHub Pages 게시

사용자가 웹 게시를 승인한 후 정적 설치용 파일만 `gh-pages` 브랜치에 게시합니다. 저장소 공개/비공개 설정은 변경하지 않습니다. 실제 AI 연결이나 비밀 키는 포함하지 않습니다.

```bash
python3 scripts/publish-pages.py
```

이 명령은 소스를 `main`, 빌드 결과를 `gh-pages`에 빠른 전진 방식으로 올립니다. 기존 이력을 덮어쓰지 않습니다. GitHub의 **Settings → Pages → Deploy from a branch → gh-pages → /(root) → Save** 설정이 필요합니다. GitHub API에 접근 가능한 경우 이 설정을 API로 확인·활성화할 수 있습니다.

예상 기본 경로는 `https://imminchea1363-dotcom.github.io/ai-office-dashboard/`입니다. Pages 설정과 실제 HTTPS 응답을 확인하기 전에는 게시 완료로 간주하지 않습니다. 브랜치 업로드와 실제 사이트 게시·사용자 휴대폰 설치는 별개의 단계입니다.
